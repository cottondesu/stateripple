# Architecture

StateRipple v0.1.0 is a generic graph state-propagation harness. It separates optional external collection (adapters), generic graph normalization, synchronous control, the risk rule, and reporting. The core (snapshot, graph, engine, rule, report) runs without Git, Go, a repository or a network. It has no third-party Go dependencies and no runtime Mandala integration. The project was previously named RiskLife; only the name and module path changed, not the computation, canonical JSON or hashes.

## Components and dependencies

| Package | Responsibility |
|---|---|
| `cmd/stateripple` | Process entry point and cancellation |
| `internal/cli` | Flags, input/output, adapter orchestration, exit codes |
| `internal/fileio` | Regular input opening, Unix nonblocking flags and pre/post identity validation |
| `internal/adapters` | Optional Git changes, offline Go package collection, Go profile validation, ownership/classification, completeness metadata |
| `internal/graph` | `Node`, `Edge`, generic structure validation (IDs, free-form kinds, endpoints, attenuation 0..3, contradictions), deterministic ordering and deduplication |
| `internal/snapshot` | Bounded JSON input, `Seed`, `Snapshot`, version/ruleset/limit/seed validation, normalization, input hash |
| `internal/engine` | Generic `Rule[S comparable]`, synchronous updates, exact state equality, limits and change waves |
| `internal/rules/risk` | Integer RiskPropagationV1, seed interpretation, maximum support and activation history |
| `internal/report` | Result model, stable arrays, JSON and human-readable output |
| `internal/canonical` | Canonical JSON encoding convention |

The CLI obtains a snapshot from either JSON or adapters, runs the risk rule over the generic engine, merges collection metadata, and formats the report. Graph and engine do not run Git or Go commands. Adapters depend on domain models; domain logic does not depend on adapters. There is no cyclic package dependency. These packages are internal reuse boundaries, not a promised public Go library API.

```text
Git + Go (optional) --> adapters --> Go profile check --> normalized Snapshot --> risk rule
Snapshot JSON (simulate) ---------> snapshot reader ---------------------------> |
                                                        v
                                                 generic engine
                                                        |
                                                        v
                                            Report + metadata
                                                        |
                                                        v
                                                JSON / Text
```

## Graph and risk rule

The core graph is generic. A node is `{id, kind}` and an edge is `{from, to, kind, attenuation}`. IDs and kinds are nonempty valid UTF-8 strings of at most 4,096 bytes; kinds are free-form labels such as `service`, `database`, `ships_to` or `depends_on`, and graph validation and propagation never derive meaning from them. The one exception in v0.1.0 is in report construction: `internal/rules/risk` lists nodes whose kind is exactly `test` and whose risk is positive in `test_targets`, and Text output uses test wording when that list is nonempty, also for `simulate` on a non-software graph. It is kept so that earlier reports stay byte-identical. Moving this projection out of the generic core, into the adapter that owns the vocabulary, is a v0.2.0 design item (report v2). Attenuation is an explicit integer 0..3 stored in each edge; negative values, 4 or more, non-integers and out-of-range numbers are rejected. Duplicate node IDs are invalid. Exact duplicate edges merge. Different edge kinds or attenuation for the same ordered endpoints are rejected as contradictory. Self-loops and cycles are accepted. Snapshot IDs may be arbitrary nonempty valid strings.

The Go adapter produces one profile of this graph. Go package IDs are `pkg:<import-path>`, and tests are `test:<import-path>`. A test node exists only when the package has active internal or external test files. External modules and standard-library packages are not graph nodes, but their resolution failures still affect completeness. An import by B of A becomes `pkg:A → pkg:B` (`prod_import`, attenuation 1). Each package with tests has `pkg:A → test:A` (`own_test`, attenuation 0). Imports by B's tests of another module-local A become `pkg:A → test:B` (`test_import`, attenuation 1). Same-package test imports are omitted in favor of `own_test`. Test nodes cannot propagate outward. `validateGoProfile` (`internal/adapters/profile.go`) checks exactly these constraints on every collected graph after generic normalization; a violation is an execution error (exit 1). Before v0.1.0 these constraints lived in the core; moving them keeps `analyze` fail-closed while letting `simulate` accept any vocabulary. Every snapshot that satisfied the former core rules normalizes to the same bytes and hash.

For each node v:

```text
next(v) = max(current(v), seed(v), max(0, current(u) - attenuation(u,v)))
```

The incoming-edge term is zero when no edge exists. Risk is an integer in 0..3 and attenuation an integer in 0..3, so a contribution never leaves 0..3 and no arithmetic overflow is possible. Multiple seeds apply their maximum value while retaining all distinct seed records and reasons. Risk never decreases. No B3/S23 Game of Life rules are used: "game-of-life style" means only synchronous generation updates of cells.

## Synchronous execution and stopping

Generation 0 is the maximum initial seed state. Every node's next value is computed from the same immutable previous-generation slice. The engine then replaces the complete state. It does not expose newly computed values to another node within that update.

Exact unchanged state confirms a fixed point. The update count includes the unchanged confirmation step, which is omitted from change waves. The default limit is 16 updates; allowed limits are 1..1024. Reaching a changing final update yields `generation_limit` and an incomplete report, even if a later update would have confirmed convergence. Empty graphs and zero-seed graphs confirm convergence in one update.

Monotonicity on the finite 0..3 state domain ensures eventual convergence for this rule, including cycles and zero-attenuation cycles. Because attenuations are nonnegative, the fixed point equals the best simple-path value, so a converged run needs at most `max(1, |V|)` updates. A zero-attenuation chain of n nodes needs exactly n updates; with the maximum limit 1024, deeper chains stop with `generation_limit` and `incomplete` rather than a false `complete`. The limit was not changed. A configured limit can still stop a run before confirmation. The generic engine does not assume monotonicity or this finite risk domain for future rules; these termination guarantees are specific to RiskPropagationV1.

## Explanation

Initial positive seeds create generation-0 changes. Each later risk increase records its prior value, new value, and every tied cause available in the preceding state that produces the new maximum. Final cells report all positive seed and incoming-edge supports that produce their final maximum, including equal support arriving later. Lower-risk seeds remain in the seed list, but are not labeled as maximum causes. Dormant cells have no positive cause and a null first activation generation.

Final causes describe maximum support in the final state; waves explain actual changes. Wave causes are well founded: following them always ends at a generation-0 seed, even with attenuation 0. Final causes are support, not origin: with zero-attenuation cycles or self-loops a cell can list a cycle neighbor (or itself) that supports its value. When a run stops at the generation limit, the final state is not confirmed as a fixed point: the last permitted update still changed a cell, and the unchanged update that would confirm convergence did not run. Four statements are kept apart: a state is mathematically a fixed point; the engine confirmed it with an unchanged update (`converged`); the engine stopped at the limit before confirming (`generation_limit`); the report is `complete`, which requires the confirmation. A limit-stopped final state can already be the fixed point (a 1025-node zero-attenuation chain with limit 1024 ends with every value final), but it is reported `incomplete` because that is unconfirmed. When it is not the fixed point, a positive cell whose supporting neighbor has since increased can have no final cause; its wave still records the cause. Such results are always `incomplete`. Their risks are lower bounds of the fixed point, and their test targets and final causes can be incomplete. The Go adapter cannot reach this state (limit 16, and Go-profile propagation converges within 4 updates); it needs `simulate` with a limit below the propagation depth, with either the generic or the Go vocabulary. Equal support without a risk increase does not create a fictitious wave. Source node and edge details permit following a path through the cells and history.

## Input collection and fail-closed behavior

All Git starts pass through command.go. Direct calls prepend `--no-lazy-fetch`; before collection, `requireGit` invokes `git --no-lazy-fetch --version` to probe option support and checks a reported version of at least 2.45.0. The installed official Git 2.45.0 release notes introduce that option; 2.44 from the audit was an estimate. A rejected option, unknown/old version or missing executable returns a requirements error without fallback. Apple Git suffixes are accepted if the numeric version and actual capability qualify. `simulate` never runs this check.

`gitOfflineEnvironment` removes conflicting inherited keys and all `GIT_TRACE*`, then appends GIT_NO_LAZY_FETCH=1, GIT_TERMINAL_PROMPT=0 and GIT_OPTIONAL_LOCKS=0. Go's policy builder starts from this environment, covering buildvcs Git children too. Production uses rev-parse/status/diff/ls-tree/ls-files/cat-file and the version capability probe. Trace removal happens before execution, without filtering real diagnostic text. These controls do not sandbox trusted tools or configured helpers.

Former embed reads use explicit source reading (Option B). `ls-tree -r -z --full-tree` enumerates the complete base tree, preserving paths containing tabs/newlines/Unicode. Regular blob modes 100644/100755 ending in `.go` are read in tree order by OID with `cat-file blob`. Gitlinks and non-Go symlink entries are not source inputs. A symlink entry ending in `.go` is rejected as an unsupported base source: Go would compile the target bytes, which are not that entry's blob, so the base scan is incomplete rather than silently skipping a possible former `//go:embed` owner. Each read must finish successfully within the 64 MiB command-output limit; missing/corrupt objects are read failures. Only sources containing `//go:embed` are parsed, retaining the existing comment/pattern semantics and avoiding new syntax errors in unrelated base sources. Every source is attempted unless context cancellation ends collection; errors include source paths/OIDs and are joined in deterministic tree order. Source bytes are held one file at a time rather than as one aggregate corpus.

Object readability is independent of whether a directive matches: present/match and present/no-match succeed; mixed missing/match, missing/no-match and multiple missing fail completeness. Git grep's exit 0 is no longer used as a completeness certificate. An existence-only preflight followed by grep would add another traversal without proving the later content reads; batch content reading could reduce process startup overhead but needs a separately audited framing/size/error protocol. The chosen implementation deliberately pays one Git process per source for a simpler read-success boundary. Peak source storage is bounded per command, while tree metadata and accumulated diagnostics/patterns grow with file count.

On any base enumeration/read/parse failure, no former ownership from that base scan is adopted. A warning includes the read diagnostic, the useful current graph yields incomplete/exit 2, and unowned documentation is unknown rather than falsely excluded. Complete base scans retain former_embed/former_test_embed and unrelated-document exclusion. Collection-preventing errors yield exit 1. No implicit fetch or object repair occurs. All tracked symlinks remain subject to current HEAD validation (NF-03).

NF-04 is an availability limitation: ignored worktree Go FIFOs can block Go before active-input validation. Default CommandContext cancellation terminates the direct child; CLI handles SIGINT/SIGTERM. SIGKILL of only the parent cannot run cleanup and can leave blocked children. There is no internal deadline or process-group supervision. P3 is deferred; mutable/shared unattended CI with generated special inputs carries a P2 operational risk. Remove special inputs, use TERM first, and force-kill an isolated job group/container as needed. Candidate work for v0.1.1 is a candidate-input preflight, deadline and platform-specific child-group control; a signal handler alone cannot solve SIGKILL.

Analysis requires a clean Git repository root containing one root Go module. Git revisions are resolved before diff execution, with command arguments separated rather than shell concatenation. NUL-separated status and path records preserve whitespace, tabs, Unicode, and newlines. Renames are deliberately treated as deletion/addition. Uncommitted and nonignored untracked files are rejected; ignored files are not.

Status is only an initial rejection check. The adapter pins the HEAD commit, reads its tree with `ls-tree -r -z`, and hashes each tracked regular file with the Git blob header and raw file bytes before and after Go collection. SHA-1 and SHA-256 object IDs are supported. Executable mode is compared on systems that expose it. The shared regular-file opener checks identity and type before/after opening; Unix uses `O_NONBLOCK`. Neither `assume-unchanged` nor `skip-worktree` can substitute for byte equality, and the index flags are never changed. Raw-byte mismatch, including clean/smudge or line-ending transformations, is an execution error. HEAD changes during collection are also errors. Symlink inputs remain unsupported/incomplete, with special-file targets rejected. Stable input during analysis is required; these scans do not make a transactional filesystem snapshot.

Git diff uses raw mode records with NUL-separated paths, no rename/external diff/textconv, and `--ignore-submodules=none`. Gitlink modes (`160000`) in either side are unknown/incomplete before document exclusions, even when the path ends in `.md`. User suppression settings do not hide committed gitlink changes. Submodule internals are outside the analysis scope.

The Go adapter reads successive JSON objects from `go list -e -json -deps -test -mod=readonly ./...`. Synthetic test variants provide dependency error evidence but do not become graph nodes. `TestImports` and `XTestImports` describe test-only edges. Both current ownership and base-commit embed directives are considered before unrelated-document exclusion, so formerly embedded Markdown remains a change source even after its directive is removed. Historical build contexts are not reconstructed; old embed pattern matches are conservative. Active source ownership is preferred; a deleted Go file can be mapped to an extant package in the same directory. Removed packages, removed last tests, inactive/build-excluded sources, and unresolvable ownership stay incomplete. Ignored source or embed files used by Go are identified as uncommitted input and make the analysis incomplete; symbolic-link inputs are also unsupported.

Every Go command (environment, build context, main module and package collection) receives one child-only policy from offlineEnvironment: GOPROXY=off, GONOPROXY=none, GOVCS=*:off, GOSUMDB=off, GOTOOLCHAIN=local, GOWORK=off, GO111MODULE=on, GOENV=off, GONOSUMDB=none, and empty GOPRIVATE/GOINSECURE/GOFLAGS/GOEXPERIMENT. Controlled inherited keys are removed before appending one value per key. List commands use -mod=readonly. Private-module proxy bypass, direct VCS and toolchain acquisition are disabled; saved Go configuration is ignored. Nonempty parent GOFLAGS/GOEXPERIMENT are reported as unsupported without applying them. Explicit GOOS/GOARCH/CGO_ENABLED and cache paths are retained; parent environment and persistent settings are unchanged. Cached modules remain usable. This acquisition policy is not OS network isolation: installed tools, wrappers and external cache helpers are trusted. Subprocess output has a 64 MiB limit per stdout/stderr stream. Partial/error dependency metadata is never silently classified complete.

The same input enumeration drives ownership and committed-input validation: Go/Cgo/test sources, production/test/external-test embeds, and `SFiles`, `CFiles`, `HFiles`, `CXXFiles`, `MFiles`, `FFiles`, `SwigFiles`, `SwigCXXFiles`, `SysoFiles`. Reported active native changes seed the package at 3 with classification `native`. Go decides field membership using the current OS/architecture, CGO and build conditions; inactive, deleted or unowned native changes remain unknown/incomplete. This uses `go list` metadata, not a successful compiler/linker invocation or an enumeration of transitive system-header includes. Ignored active inputs make metadata incomplete.

Build context records Go version, target OS/architecture, CGO setting, module identity, and build-condition tags. It does not include checkout paths or timestamps. Repository workspace files and an explicit non-off GOWORK environment, nested modules, reachable directory replacements, custom GOFLAGS and experimental build configurations are conservatively unsupported. The analyzer does not execute generators, build every platform, or prove all runtime dependencies are represented.

Go's replacement metadata defines the kind: absent Replace.Version identifies a directory replacement; nonempty version identifies a remote replacement even when its Dir is cached locally. Classification covers packages emitted by current go list -e -deps -test ./..., not all replace directives. Unused local/remote replacements, including missing unused directories, do not alone change completeness. Reachable directory replacements are incomplete; cached versioned remote replacements are supported. Reachable unresolved local/remote dependencies are incomplete through Incomplete, Error or DepsErrors. Workspace/nested-module restrictions apply independently. A go.mod change seeds every main-module package regardless of directive use.

## File output and Text display

The shared JSON/Text writer rejects an empty path or trailing OS separator before calling any path-normalization helper. It inspects the original argument with Lstat before resolving Dir/Base, so an existing directory cannot be reinterpreted as dir/dir. A second inspection applies to the resolved destination; exclusive os.Link remains the publication authority in a race. Existing aliases and metadata protection remain intact.

Snapshot paths must resolve to regular files. Regular symlink inputs are permitted, but FIFO/device/socket/directory inputs are rejected before opening and file identity is checked after opening. Non-Unix fallback opens retain a check/open race; the Unix open path is exercised on macOS arm64 (local) and Linux (arm64 local container, amd64 GitHub Actions), and non-Unix platforms remain untested.

The CLI retains opened input identity until output and rejects aliases. v0.1.0 permits only a nonexistent output entry: Lstat rejects regular files, hardlinks, symlinks (including dangling links), directories and special files without modifying bytes, inode identity, ownership, permissions, ACLs or xattrs. It resolves and records parent identity, creates a same-directory private temporary file, writes all bytes, chmods 0600, syncs and checks close, then rechecks parent identity. os.Link(tempName, destination) publishes atomically: any existing destination, even created after Lstat, makes publication fail without replacement. Unsupported filesystems have no rename fallback. The temporary name is removed on return. Cleanup failure is joined with the primary error; after publication the diagnostic explicitly states output is already published (CLI exit 1). At most one concurrent writer succeeds while directory and winning entry are retained. Trusted, stable parents and temporary names are required: malicious substitution after the check, same-inode changes and parent ABA are not fully prevented. A moved directory or crash may leave a temporary link. No directory fsync/crash-durability guarantee is made. POSIX permissions are measured on Darwin; runtime publication is also exercised on Linux (amd64 on GitHub Actions, arm64 in a local container), including the concurrent-writer and metadata checks, while Windows runtime publication and Windows ACL semantics remain unverified.

Text output is mode dependent: the Git "Changed files" section appears only for analyze reports (build context present or changes recorded), and the test-target section plus the "Selected tests have not been executed" note appear only for analyze reports or when the graph yields `test` targets. Generic simulations end with "Risk is a propagated priority, not a probability." Text output renders untrusted strings through `strconv.QuoteToGraphic`, retaining graphic Unicode and exposing newline, CR, tab, ESC and other nongraphic characters as escapes. Fixed report structure remains literal. This display boundary does not mutate the report or alter canonical JSON/hash input.

Stderr diagnostics have their own boundary. Paths, revisions, flag names and Git/Go tool output reach them inside wrapped errors (`*os.PathError`, `*os.LinkError`, joined errors), so `cli.Run` escapes the complete formatted message once instead of each call site: every rune that `strconv.IsGraphic` rejects and every invalid UTF-8 byte becomes the same Go escape the text report uses, and each diagnostic is exactly one line, including joined errors and multi-line tool output. Backslashes and quotes are not escaped, so ordinary and Windows paths are unchanged and `%q`-quoted values are not escaped twice; a literal backslash sequence in a name is therefore indistinguishable from an escape, which does not affect the terminal or the log structure. The `flag` package no longer writes to stderr itself: `Run` prints the escaped parse error and the unchanged usage text. Help, usage and version writes are checked; a failed or short write exits 1. File-system paths themselves, reports, canonical JSON and hashes are not touched.

## Determinism

Normalization orders nodes, edges and seeds, merges only specified duplicates, and validates before execution. Map lookup may locate a node, but map iteration never controls propagation or emitted ordering. Rules use integer arithmetic and serial updates. Reports sort cells, causes, waves, warnings, changes, and test targets. Canonical bytes have fixed field order and one final newline. Hashing uses only the normalized engine snapshot; Git metadata and build context remain separate. See [SCHEMA.md](SCHEMA.md) for all keys and ordering.

The guarantee is conditional on identical normalized engine inputs, rule identifier, and update limit. Adapter collection can vary when repository state, dependencies, build environment, or toolchain changes. This separation avoids claiming reproducibility across different analysis inputs.

## Future extension

The generic engine compares arbitrary comparable state and delegates updates to a rule. Graph ordering, synchronous control, convergence checks and limits are reusable. Risk values, seed meaning, traces and test-target projection remain risk-specific. A second rule would add a `ruleset` dispatch in one place (the CLI currently calls `risk.Run` directly) and, for another state type, a new ruleset or schema version; non-monotone or Conway-style rules would also need declared completion criteria and cycle detection. A different risk range (for example 0..5) would be a new or versioned rule so that RiskPropagationV1 inputs and hashes stay valid. v0.1.0 adds no speculative plugin framework, stdin input, explicit-input adapter or second rule.

## Upstream contracts

Adapter contracts follow [Go command documentation](https://pkg.go.dev/cmd/go) and [Go Modules reference](https://go.dev/ref/mod), including package fields, replacement and environment policies. Output uses [os.Link](https://pkg.go.dev/os#Link), implemented with Unix link and Windows CreateHardLink; errors have no unsafe fallback. Git byte parsing follows [git diff](https://git-scm.com/docs/git-diff) and [git status](https://git-scm.com/docs/git-status). StateRipple uses installed tools and does not automatically install Git, Go, or Mandala.
